# 운영 장애·백업·복구 절차

기준일: 2026-07-22

## 장애 발생 직후

1. 실제 결제 버튼을 닫거나 Cloudflare 환경변수의 결제 정책을 비활성화해 신규 거래를 멈춥니다.
2. Cloudflare Pages 배포 ID, Supabase 로그 시간대, 영향받은 사용자·거래 ID를 기록합니다.
3. 결제 장애라면 Toss 거래를 임의로 재승인하지 않고 주문 ID로 승인·취소 상태를 먼저 대조합니다.
4. 분쟁·환불·정산 관련 거래는 관리자 화면에서 보류 상태로 유지합니다.

## 서비스 복구 우선순위

1. 로그인과 공개 상품 조회
2. 결제 승인·웹훅의 중복 처리 방지
3. 작업방 제출·수정·분쟁 기록
4. 환불·정산 기록
5. 이미지와 부가 화면

## Cloudflare 복구

1. 실패한 배포의 빌드 로그와 커밋 SHA를 기록합니다.
2. 직전 정상 Production 배포로 롤백합니다.
3. 환경변수는 값을 노출하지 않고 키 이름과 설정 여부만 비교합니다.
4. `/`, `/login`, 상품 상세, 결제 성공·실패 복귀 주소를 확인합니다.

## Supabase 복구

현재 운영 프로젝트는 Free 플랜이며, 대시보드에서 예약 백업이 제공되지 않는 것을 2026-07-22에 확인했습니다. 실제 결제를 열기 전 아래 둘 중 하나를 완료해야 합니다.

- 권장: Pro 플랜으로 전환하고 최대 7일 예약 백업이 실제 생성되는지 확인합니다.
- 대안: 운영 DB를 암호화된 외부 저장소에 수동 백업하고 별도 Supabase 프로젝트에서 복원 리허설을 완료합니다. 백업 파일은 Git 저장소에 커밋하지 않습니다.

복구 순서:

1. Database Backup 화면 또는 암호화된 수동 백업에서 사용 가능한 시점과 보존 기간을 확인합니다.
2. 데이터 복원 전 현재 DB와 Storage의 상태를 별도 기록합니다.
3. 운영 프로젝트에 바로 덮어쓰지 않고 별도 복구 프로젝트에서 스키마·행 수·핵심 거래를 검증합니다.
4. 마이그레이션은 `supabase/baseline.manifest.json`과 운영 migration history를 대조합니다.
5. 복구 후 RLS, Edge Function 활성 버전, Auth Redirect URL, Storage 정책을 다시 점검합니다.

## 결제·정산 대조

1. 긱온의 주문 ID와 Toss 결제 키·상태를 1:1로 대조합니다.
2. 성공 웹훅이 누락된 거래만 재조회하며 동일 주문을 새로 승인하지 않습니다.
3. 환불·지급 완료는 은행 또는 Toss의 실제 결과를 확인한 뒤 관리자 기록을 갱신합니다.
4. 금액 불일치는 자동 정산하지 않고 수동 검토 대상으로 보류합니다.

## 완료 조건

- 정상 배포 커밋과 복구 시각이 기록됐습니다.
- 결제·환불·정산 건수가 외부 제공자 기록과 일치합니다.
- 제출·수정·분쟁 증거가 유지됩니다.
- 원인, 영향 범위, 재발 방지 항목을 운영 기록에 남겼습니다.
- 예약 백업 또는 암호화 수동 백업의 생성 시각과 별도 프로젝트 복원 결과가 기록됐습니다.
