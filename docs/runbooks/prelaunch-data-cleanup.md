# 출시 전 테스트 데이터 정리 절차

기준일: 2026-07-22

## 구분 기준

- 앱 데모 데이터: ID가 `demo-`로 시작하며 `src/data/demoAccountData.ts`에서 브라우저 로컬 저장소에만 생성됩니다. 운영 Supabase 데이터가 아닙니다.
- 스키마 검증용 계정: `@synthetic.invalid` 주소와 `10000000-0000-4000-8000-*` UUID를 사용합니다. `supabase/roles.fixture.json`에 `localOnly: true`로 선언되어 있으며 운영 DB에 넣지 않습니다.
- 운영 리허설 데이터: 실제 로그인 계정으로 만든 상품·문의·제안·거래입니다. 제목 앞에 `[테스트]` 또는 `[출시점검]`을 붙여 식별합니다.
- 실제 공개 데이터: `[테스트]`, `[출시점검]` 표시가 없고 운영자가 공개를 승인한 상품과 거래입니다.

## 정리 순서

1. 운영 Supabase에서 `@synthetic.invalid`, `demo-%`, 제목의 `[테스트]`와 `[출시점검]`을 각각 조회합니다.
2. 결제·환불·정산 기록이 연결된 리허설 거래는 삭제하지 않고 관리자 화면에서 완료·취소 상태와 식별 문구를 유지합니다.
3. 결제 기록이 없는 리허설 상품과 문의만 운영자 확인 후 숨김 또는 삭제합니다.
4. Storage의 상품 샘플은 해당 상품의 참조 여부를 확인한 뒤 고아 파일만 삭제합니다.
5. 공개 상품 목록, 관리자 거래 목록, 정산 목록을 다시 열어 남은 테스트 표기를 확인합니다.
6. 삭제 수량과 보존한 거래 ID를 출시 점검 기록에 남깁니다.

## 완료 조건

- 운영 Auth에 `@synthetic.invalid` 계정이 없습니다.
- 공개 상품 제목에 `[테스트]` 또는 `[출시점검]`이 없습니다.
- 결제·환불·정산 증거는 삭제되지 않았습니다.
- 고아 Storage 파일만 정리됐고 공개 상품 이미지가 정상 표시됩니다.
